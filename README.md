# Trajectory backend task

Решение оптимизирует ночную синхронизацию AmoCRM -> PostgreSQL. `sync.collect_leads_customers` принимает CRM итераторы и SQLAlchemy session, поэтому тестируется без реального API и запуска инфраструктуры.

## Что было дорого и исправлено

- Исходный проход выполнял поиск и `commit` для каждой записи, а обновления JSONB адресовались индексами массива. Ошибка в вычислении индекса могла перезаписать не ту запись или выйти за границы.
- Теперь сущности обновляются в памяти пачкой, изменения фиксируются одной транзакцией; итераторы CRM не материализуются целиком. Ошибка источника или БД вызывает rollback.
- Покупатель ищется сначала по AmoCRM ID, затем по уникальному логину среди сделок. Сделка — по ID, затем по уникальному логину покупателя. При конфликте сохраняется запись, найденная по ID сделки, данные другой записи объединяются.
- Удаление запускается только после успешного завершения обоих источников и лишь при `is_full=True`. Неполный запуск сохраняет данные. Полная выгрузка удаляет отсутствующие записи и очищает отсутствующие/помеченные «удалить» сущности.
- JSONB формат сохранён; GIN индексы добавлены для containment-поиска.

## Ресурсы и запросы

Память итераторов ограничена размером страницы API и `batch_size` (по умолчанию 500). Для разрешения identity коллизий и полного удаления загружаются существующие строки и их JSON-поля: при 70 тыс. строк это ориентировочно 100–300 МБ Python-памяти, сильно зависит от размера `api_value`. Для очень крупных вложенных payload потребуется перенос identity-индексов в отдельные колонки/таблицы.

Синхронизация делает один запрос для начального чтения, ориентировочно один `flush` на каждый пакет (до 140 при 70 тыс. входных записей), один запрос выборки для финальной чистки, плюс пакетные INSERT/UPDATE/DELETE, которые SQLAlchemy может разбить по лимитам драйвера. Это вместо минимум 70 тыс. поисков и 70 тыс. commit-ов. Cleanup сохраняет один полный scan, потому что должен определить отсутствующие записи.

## Запуск

Подключите `db` к Flask-приложению и передайте генераторы объектов CRM:

```python
collect_leads_customers(db.session, amocrm_get(Customer, ...), amocrm_get(Lead, ...), is_full=True)
```

Необходимы Python 3.9+, Flask-SQLAlchemy и PostgreSQL.
